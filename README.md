# Модуль прогнозирования времени выполнения заявок и мониторинга SLA в службе технической поддержки

Монорепозиторий курсового проекта по теме 16: **«Проектирование модуля прогнозирования времени выполнения заявок в службе технической поддержки на основе регрессионной модели машинного обучения (учитываются категория заявки, приоритет, исполнитель, загруженность специалистов, история аналогичных обращений и SLA)»**.

## ⚡ Быстрый запуск

### 1. База данных PostgreSQL
База данных `itsm_dashboard` уже создана и настроена на локальном PostgreSQL (`localhost:5432`, логин/пароль: `postgres` / `postgres`).
Либо можно поднять через Docker:
```bash
docker compose up -d postgres
```

### 2. Запуск бэкенда (Go)
Из папки `backend`:
```bash
cd backend
go run ./cmd/server
```
При старте сервер автоматически:
* Создает таблицы в PostgreSQL
* Загружает начальные 250 заявок из `data/character_problems.json` (44 оперативных инцидента + 206 исторических закрытых обращений)
* Запускает расчет скорингов единой регрессионной модели ML (прогноз времени выполнения, риск срыва SLA и маршрутизация)
* Поднимает HTTP API и стрим Server-Sent Events (SSE) на порту `8080`
* Автоматически раздает SPA фронтенд на `http://localhost:8080/`

### 3. Запуск фронтенда (React)
* **Готовый билд:** Уже встроен в бэкенд и доступен по адресу **[http://localhost:8080](http://localhost:8080)**.
* **В режиме разработки (Hot-Reload):**
  ```bash
  cd frontend
  npm run dev
  ```
  Фронтенд запустится на `http://localhost:3000` с автоматическим проксированием запросов к бэкенду.

## 🤖 Единая регрессионная модель машинного обучения

В проекте реализована **единая регрессионная модель машинного обучения (`GradientBoostingRegressor`, `gbdt_reg_v2.0`)**, объединяющая прогноз времени выполнения, оценку риска срыва SLA и подбор оптимальной команды/исполнителя:

* **Файлы:** `backend/models_ai/time_regression.onnx` и `time_regression_model.json`.
* **Что делает:**
  1. Прогнозирует точечное время выполнения $T_{\text{pred}}$ и 80%-й квантильный доверительный интервал $[T_{\min}, T_{\max}]$ с учётом исторической медианы аналогичных заявок, текущей очереди команды и исполнителя, коэффициента скорости специалиста, приоритета, срочности, рабочих часов и текстовых маркеров.
  2. Рассчитывает вероятность и статус риска срыва SLA (`SAFE`, `WARNING`, `CRITICAL`) и запас времени до дедлайна.
  3. С помощью встроенных TF-IDF профилей команд и регрессионной оценки SLA ранжирует Top-3 команды назначения (кнопка **«Передать»** в 1 клик) и предлагает менее загруженного специалиста.
  4. Выделяет Топ-3 фактора влияния на прогноз и поддерживает API `POST /api/v1/predict`, `GET /api/ml/metrics` и `GET /api/incidents/export`.

### Трекинг предсказаний ML и обратная связь (`ai_predictions`)
* В таблицу PostgreSQL `ai_predictions` логируются предсказания регрессионной модели (рекомендованная команда, уверенность, прогноз длительности `predicted_minutes`, риск SLA `predicted_sla_risk`, вектор фичей).
* При действиях диспетчера фиксируется `is_accepted: true/false` и фактическое время решения для расчёта живой ошибки и дообучения.
* Подробнее в [docs/ai_predictions_tracking.md](docs/ai_predictions_tracking.md) и [docs/sla_prediction_model.md](docs/sla_prediction_model.md).

## 🎯 Демонстрационные сценарии (Live Demo)

В нижнем правом углу дашборда расположена интерактивная **Панель живой демонстрации**:
1. **«+ Критический»**: Мгновенно генерирует аварийный инцидент наивысшего приоритета (`MediaCore`). Дашборд воспроизводит звуковой сигнал, выводит всплывающий алерт и помещает карточку в красную колонку с таймером SLA.
2. **«+ На координатора»**: Генерирует инцидент, назначенный на координаторов. Дашборд подсвечивает подсказку ИИ с рекомендованной командой и предлагает кнопку быстрой передачи.
3. **«Решить инцидент»**: Завершает критический сбой и переводит его в статус «Завершен», демонстрируя автоматическое обновление без перезагрузки страницы.
4. **«Сброс»**: Возвращает базу в исходное состояние файла `character_problems.json`.
